# 引擎与技术路线决策 · 《I Can Cook For You From Here》

> 结论先说：**沿用原版的「视觉小说」模式，不要改成 2D 横版或 RPG。**
> 技术实现上，用 **Ren'Py 的剧本结构 + 浏览器原生运行**（见第 4 节）。

---

## 1. 先定位原作是什么形态

| 项 | 原作 *I Can Smell You From Here* |
|---|---|
| 类型 | 视觉小说 / 心理恐怖 / 黑色喜剧（带恋爱外壳） |
| 引擎 | Godot（网页可玩，另有 Windows / Linux / Android 版本） |
| 交互 | 只有两类：**推进对白** + **选择回复** |
| 结构 | 一段连续对白树，5 个结局，通关后给"心理评估" |
| 时长 | 单周目 15–30 分钟 |
| 作者 | catproblem9735（写作、美术、动画、音乐、音效、程序全一人） |

关键点：**它的"游戏性"完全长在对白上**。没有任何移动、探索、战斗、物品栏。你唯一的动词是"说话"。

---

## 2. 三种模式的取舍

| 方案 | 是什么 | 对这个同人项目的判断 |
|---|---|---|
| **A. 沿用视觉小说（推荐）** | 立绘 + 背景 + 对白框 + 选项分支 | ✅ 与原作同一类型契约，玩家一秒就知道怎么玩；美术复用率最高；一个人也能做完 |
| B. 2D 横版 / 冒险解谜 | 走位、点击场景、背包、场景切换 | ⚠️ 会把"看她的脸、听她说话"的注意力切碎。原作的恐怖来自**不能逃跑**——你能走动，恐怖就漏气了 |
| C. RPG / 养成数值 | 地图、日程、属性数值、好感度面板 | ⚠️ 数值面板会把她变成"攻略对象"，恋爱感反而变廉价；工作量至少 ×5（地图、行走图、UI、战斗/日常循环） |

**为什么 A 是对的选择（三个理由）**

1. **凝视就是玩法。** 原作最狠的一招是让你坐在原位，看她笑，看她停顿，看她把一句话说完。镜头不动，压力才会累积。任何"让我去别处看看"的设计都会稀释这一点。
2. **成本结构。** VN 的成本 = 剧本 × 美术（背景 / 立绘 / CG）× 对白系统。RPG 额外要地图、行走图、触发器、数值平衡、战斗或日常循环——而这些东西对"恋爱张力"几乎零贡献。
3. **可玩性可以加在骨架上，不必换骨架。** 我想做的"嗅"交互、厨房调味小游戏，都可以做成 **对白间隙的 30 秒 2D 小交互**（Ren'Py 支持 `screen` + `imagebutton`，自定义 Web 引擎里就是一个 canvas 层），**不改变主循环**。这就是很多优秀 VN 的做法：主线是 VN，关键处插一段小玩法当"呼吸"。

> 一句话：**类型不要去"改编"，要去"加深"。** 原作是 VN，同人续篇也该是 VN；我们的创新放在演出、气味系统、承诺账本这些**只有 VN 才能做得好的东西**上。

## 3. 现有内容如何迁移（剧本工作量估算）

按业界经验，第一作应该短：单路线 1 万字以内先跑通，再扩写。本作规模规划：

| 章节 | 场景数 | 立绘表情差分 | CG | 字数（中） |
|---|---|---|---|---|
| Ch0 重制第一夜 | 1（小酒馆） | 8 | 1 | 2,500 |
| Ch1 门铃 | 2（玄关 / 厨房） | 6 | 1 | 3,000 |
| Ch2 刀与糖 | 1（厨房） | 8 | 2 | 3,500 |
| Ch3 冰箱 | 2 | 5 | 1 | 2,000 |
| Ch4 早餐 | 1 | 6 | 3 | 2,500 |
| **合计** | **7 张背景** | **~24 张差分** | **8 张 CG** | **~13,500 字** |

立绘用**两层分层法**：`base（身体+服装）` + `face（表情差分）`，只换表情层，工作量直接砍一半。这是 VN 美术的标准做法。

## 4. 引擎选型

### 候选对比

| 引擎 | 优点 | 对本站的缺点 |
|---|---|---|
| **Ren'Py 8.5.x**（2026-05 最新 8.5.3） | VN 事实标准；label 分支、存档、回滚、多语言全是现成的；可导出 Windows / macOS / Linux / Android / iOS / **浏览器** | 需要装 SDK 打包；网页版要自己在服务器托管构建产物，移动浏览器要额外调优 |
| **Godot 4.x**（原作的选择） | 自由度高，能塞小游戏；web 导出成熟 | 多线程 web 导出需要 **COOP/COEP 跨源隔离头**（`SharedArrayBuffer`），否则掉到单线程甚至起不来；VN 专用的存档、回滚、历史、自动播放都要自己写 |
| **Unity** | 生态大 | 对纯 VN 太重，web 包体大 |
| **网页原生 (HTML/CSS/JS) 轻量 VN 内核** | 零安装、秒开、可直接嵌在本站/itch 的 iframe 里；一个文件就是游戏；改一行刷新就见效 | 存档、回滚、历史、自动播放、多语言需要自己实现（约 400–600 行，可控） |

### 我的建议：**两条腿，但先走网页原生这条**

1. **现在（Vertical Slice / 可玩演示）**：网页原生轻量 VN 内核。
   - 理由：这个项目要在浏览器里直接给你试玩；不需要构建、不需要 SharedArrayBuffer 头、不受 host 限制；我能当场调演出（烛光呼吸、立绘推近、气味叠加）。
   - 剧本仍用 **Ren'Py 语法风格的 `.rpy`-like 数据文件**（`label` / 对白 / 选项 / `if` 条件），所以后期搬去 Ren'Py 是复制粘贴级别的迁移，不是重写。
2. **日后要上 Steam / itch 独立包**：把同一份剧本喂给 Ren'Py 8.5.3 出 Windows/Linux/Android 版。
   - 若要还原原作的"Godot 网页分发"，注意平台要发 `Cross-Origin-Opener-Policy: same-origin` 与 `Cross-Origin-Embedder-Policy: require-corp`，否则多线程 web 构建会失败。

**不要做的事**：为了"看起来更像游戏"去加地图或战斗。原作者的强项是**一个人把对白、表情、音乐扣到极致**，我们要赢的是同一个维度。

## 5. 开发计划（可执行）

- **M0 概念（已完成）**：主视觉锁定、剧本大纲、引擎决策 ← 本文件
- **M1 Vertical Slice（2 周量）**：Ch0 重制第一夜完整可玩（网页），含 1 背景 + 1 立绘 × 8 表情 + 对白系统 + 3 结局分支 + 气味交互原型
- **M2 系统层**：三量表（隐藏）、承诺账本、嗅模式、结局存档、双语切换
- **M3 内容扩充**：Ch1–Ch3
- **M4 终章 + 打磨**：Ch4、8 张 CG、音乐 4 首、音效、心理评估页
- **M5 发布**：itch.io 页面（免费，注明非官方同人、原作者 catproblem9735、原作链接）

### 里程碑验收标准（避免"永远做不完"）
- 每个 Milestone 结束时必须**能在浏览器里从头玩到章节结束**，不允许"只差美术"的半成品状态。
- 所有占位素材用色块 + 文字标注（`[BG: 厨房 / 夜]`），先保证流程通，再替换。
